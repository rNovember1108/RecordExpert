### 2.1 [src/model/service/RecordingService.h](file:///d:/Work/RecordExpert/src/model/service/RecordingService.h)

RecordingService 封装 ScreenRecorder 完整生命周期 + 从 UI 状态到 RecorderOptions 的校验组装。纯 C++ 类(无 QObject，可独立单测)。

```cpp
namespace re {

class RecordingService {
public:
    RecordingService() = default;
    ~RecordingService() = default;

    bool Start(RecorderOptions opts);
    bool Stop();
    bool Pause();
    bool Resume();
    bool IsActive() const;

    struct StartResult {
        bool ok = false;
        QString status;   // ViewModel.setStatus 用
        QString error;    // ViewModel emit errorOccurred 用(可为空)
    };

    struct UiState {
        QString output_path;
        int speed_multiplier = 1;
        QString video_device;              // "desktop"/设备名/"composite"
        QString secondary_video_device;
        QString audio_device;              // "mixed"/设备名
        QString primary_audio_device;
        QString secondary_audio_device;
        int record_mode = 0;               // 0=全屏 1=区域 2=窗口
        QString window_title;
        int region_offset_x = 0, region_offset_y = 0;   // 物理像素
        int region_width = 0, region_height = 0;
    };

    StartResult StartFromUiState(const UiState& state);

private:
    std::unique_ptr<ScreenRecorder> recorder_;
};

}  // namespace re
```

`StartFromUiState` 内部顺序：前置校验(composite 必须选副摄像头 → mixed 必须选主/副音频设备 → 窗口模式必须选标题 → 区域模式 width/height 必须 >0) → 组装 RecorderOptions(后端映射：空/desktop→gdigrab、composite→composite 且 device 固定 "desktop"、其他→dshow；mixed→audio_backend="mixed" 且 device=primary) → `Start(std::move(opts))`。`Start` 内部先 `recorder_.reset()`，再 `make_unique<ScreenRecorder>` 并 `Start(0)`(0 = 无限时)。

### 2.6 [src/model/capture/i_video_source.h](file:///d:/Work/RecordExpert/src/model/capture/i_video_source.h)

IVideoSource 抽象接口(策略模式)。所有采集后端都实现此接口；`Run` 由协调器在专用 worker 线程调用。

```cpp
namespace re {

struct VideoOptions {
    int fps = 30;
    int64_t bit_rate = 4'000'000;
    int offset_x = 0, offset_y = 0, width = 0, height = 0;
    int speed_multiplier = 1;
    std::string window_title;
    std::string device;
    std::string secondary_device;
};

class IVideoSource {
public:
    virtual ~IVideoSource() = default;
    virtual bool Open() = 0;
    virtual bool Run(double duration_seconds,
                     std::chrono::steady_clock::time_point start,
                     const std::atomic<bool>& stop) = 0;
    virtual void Close() = 0;    // 幂等
    virtual void Pause() = 0;
    virtual void Resume() = 0;
};

}  // namespace re
```

具体实现类(均在 `src/model/capture/` 下):

| 类 | 后端 | Open() 内部 | Run() 内容 | Close() 释放 |
|----|------|------------|-----------|-------------|
| GdiGrabVideoSource | gdigrab 桌面 | avdevice_register_all → OpenInput → OpenEncoder(mpeg4) → InitScaler | 暂停时 sleep 10ms 不抓帧 → 读帧 → 倍率抽帧 → DrawLabelWatermark/DrawTimestampWatermark → sws_scale → EncodeAndWrite | in_fmt_ctx_ / dec_ctx_ / enc_ctx_ / sws_ctx_ / yuv_frame_ |
| DShowVideoSource | dshow 摄像头 | OpenInput → OpenEncoder → InitScaler | 暂停时持续读包丢弃 → 读帧 → 倍率抽帧 → sws_scale → EncodeAndWrite | 同上 |
| CompositeVideoSource | gdigrab 主 + dshow 副 | OpenMainInput → OpenCameraInput → OpenEncoder → InitScalers | 主循环读桌面帧 → 水印 → sws_scale → BlitPiP(叠加最新摄像头帧) → EncodeAndWrite；摄像头独立线程 drop-old | 两路 in_fmt/dec + enc + sws + cam_thread_.join |

### 3.1 录制启动

```

   │   其他 → dshow

      └─ recorder_->Start(0)

         │  ├─ video_->Open()        // 失败 → Close(),Start 返回 false
```

### 3.2 录制 Run 循环

```
video_->Run()（GdiGrab / DShow 单路）:
  while (!stop) {
    if (paused_) { 首次记录 pause_start_; [GdiGrab] sleep 10ms; [DShow] av_read_frame + unref 丢弃; continue; }
    elapsed = now - start - total_paused_          // duration_seconds>0 时到点 break
    av_read_frame → EAGAIN 等 1ms / AVERROR_EXIT 正常收尾
    avcodec_send_packet → avcodec_receive_frame → dec_frame
    speed>1 且 (++seen_ % speed)!=0 → av_frame_unref 丢帧
    av_frame_make_writable(dec_frame)
    [GdiGrab / Composite 主源] DrawLabelWatermark(dec_frame, kWatermarkLabel) + DrawTimestampWatermark(dec_frame)
    [Composite] sws_scale → yuv_frame_ 后 BlitPiP() 叠加最新摄像头帧
    [其余] sws_scale(dec_frame → yuv_frame_)
    pts = llround(elapsed * fps / speed)
    if (pts <= prev_pts) pts = prev_pts + 1         // 撞槽强制单调
    writer_.EncodeAndWrite(enc, stream, yuv_frame_)
  }
  writer_.EncodeAndWrite(enc, stream, nullptr)      // flush 编码器

audio_->Run():
  while (!stop) {
    if (paused_) { av_read_frame + unref 丢弃(防 rtbufsize 溢出); EAGAIN 等 1ms; continue; }
    av_read_frame → avcodec_send/receive → dec_frame
    swr_convert(dec_frame → FLTP)
    speed>1 → 每 speed 个样本保留 1 个(kept=(converted+speed-1)/speed)
    av_audio_fifo_write(fifo_)
    while (fifo >= frame_size 1024) DrainFifo(false)
  }
  DrainFifo(true)                                   // flush 残帧
  writer_.EncodeAndWrite(enc, stream, nullptr)      // flush 编码器

MixedAudioSource::Run():
  PumpOne(主) + PumpOne(副) → fifo_a_ / fifo_b_ → MixOne()(取较短一侧等权 0.5+0.5) → fifo_out_ → DrainFifo
```

`DrainFifo` 的 PTS：正常帧按墙钟换算 `llround(elapsed * sample_rate / speed)`；flush 残帧用 `prev_pts_ + frame_size` 接续；`pts <= prev_pts_` 时强制 +1。

## 5. 线程模型

| 线程 | 入口 | 退出条件 | 清理 |
|------|------|----------|------|
| GUI 主线程 (QGuiApplication) | QML 事件循环 | app.exec() 返回 | — |
| 视频采集线程 | IVideoSource::Run() (GdiGrab / DShow / Composite 主循环) | stop_requested_ → InterruptCallback → av_read_frame AVERROR_EXIT | video_->Close() |
| 音频采集线程 | IAudioSource::Run() (DShow / Mixed) | 同上 | audio_->Close() |
| 摄像头线程(仅 Composite) | CompositeVideoSource::CameraThread() | cam_stop_ + stop_requested_ | Close 内 cam_thread_.join() |
| 解码线程(播放器) | PlaybackDecoder::run() | stop_ 置位 或 av_read_frame EOF | stop() + wait() + close() |
| Qt 音频线程(播放器) | AudioPullDevice::readData → AudioPlayer::pullRead | QAudioOutput 停止 | close() 内主线程销毁 QAudioOutput |
| 场景图渲染线程 | VideoPlayerItem::updatePaintNode | 窗口销毁 | 节点/纹理由场景图回收 |

**共享状态保护:**

| 对象 | 保护方式 |
|------|----------|
| Mp4Writer 写包 | std::mutex write_mutex_ |

| 两轨共享 capture_start_ | 无锁(先写后启动线程) |

## 6. PTS 时间轴

```
录制时(所有采集源共用同一零点 capture_start_):
  video PTS = llround((wall_clock - capture_start_ - total_paused_) × fps / speed)
  audio PTS = llround((wall_clock - capture_start_ - total_paused_) × sample_rate / speed)
  音轨 flush 残帧: pts = prev_pts_ + frame_size(接续,不按 flush 时刻墙钟打戳)
  撞槽保护: pts <= prev_pts → pts = prev_pts + 1(严格单调)
  暂停总时长: total_paused_ 从 wall_clock_ 扣除,暂停期间不推进
  倍率抽帧: speed>1 时视频每 speed 帧保留 1 帧,音频每 speed 个样本保留 1 个

播放器时钟:
  音频可用: audioClockMs = audio_start_pts_ms_ + input_samples_total×1000/rate
                            - old_ring×prev_speed×1000/rate - new_ring×speed×1000/rate
            target_pts = max(audioClockMs(), position_ms_)
  无音频:   target_pts = start_pts_ + playback_clock_.elapsed() × speed(墙钟降级)
```

## 7. FFmpeg 资源管理原则

1. **Close() 幂等**:所有 Close 方法每个成员 `if (ptr)` 守卫,可安全处理部分初始化状态。
2. **OpenInput 失败统一 Close()**:所有 Source 的 OpenInput 用 `do-while(false) + if(!ok) Close()`。
3. **音频轨降级不中断录制**:ScreenRecorder::Open 中 `audio_->Open()` 失败 → `audio_.reset()` + `capture_audio=false`；PlaybackDecoder 音频段失败只清音频资源,不销毁已打开的视频上下文。
4. **OpenOneInput 逐分支自清理**:MixedAudioSource 的 OpenOneInput 每个失败分支手动清理上游资源。
5. **avformat_alloc_context 必须在 open_input 前**:这样才能挂 interrupt_callback 让停止时阻塞中的 av_read_frame 立即返回 AVERROR_EXIT。打开阶段 stop_flag_ 为空时回调放行。
6. **所有退出路径 flush 编码器**:视频 `EncodeAndWrite(nullptr)`、音频 `DrainFifo(true) + EncodeAndWrite(nullptr)`。
7. **yuv_frame_ 不在循环内 unref**:它是 InitScaler/InitScalers 一次性分配、循环复用的输出缓冲,否则表现为"只录到 1 帧"。
8. **stream_ 归 Mp4Writer 所有**:Source::Close 只置空指针,不释放 AVStream。

## 8. 为什么录屏和录音都需要解码

### 核心原因

FFmpeg 的下游 API（sws_scale、swr_convert、编码器、滤镜）**只认 AVFrame，不认 AVPacket**。解码是 FFmpeg 强制要求的"packet → frame"转换层。

视频和音频虽然都走 `avcodec_send_packet → avcodec_receive_frame`，但背后的必要性程度完全不同。

### 视频录屏（gdigrab：BMP 解码器）

gdigrab 输出的不是 rawvideo，而是 **BMP**：每个 AVPacket 是 `[BITMAPINFOHEADER(40 字节) + BGR0 裸像素]`，`codecpar->codec_id = AV_CODEC_ID_BMP`。所以 `avcodec_find_decoder(codecpar->codec_id)` 拿到的是 **BMP 解码器**（libavcodec/bmp.c），不是 rawdec。截图路径同理，[Screenshot.cpp](file:///d:/Work/RecordExpert/src/model/Screenshot.cpp#L66-L69) 的注释明确写了 "gdigrab 在 read_header 里已经把 codecpar->codec_id(AV_CODEC_ID_BMP)填好"。

BMP 解码器做得很轻：解析 40 字节头拿到宽高/位深/像素格式 → 输出 BGR0 AVFrame → 拷贝像素（DIB 为 bottom-up 时翻转行序）。

```c
// FFmpeg libavcodec/bmp.c 的核心(简化)
// 1. 从 pkt->data 前 40 字节解析 BITMAPINFOHEADER
// 2. 按头里的 biWidth/biHeight/biBitCount 建 BGR0 AVFrame
// 3. 从 pkt->data + 40 处拷贝像素(必要时做 bottom-up 行序翻转)
```

| 维度 | 说明 |
|------|------|
| 解码前格式 | AVPacket, codec_id=BMP, data=[40B 头 + 裸 BGR0 像素] |
| 解码后格式 | AVFrame, format=BGR0, data[0]=[BGR0 像素] |
| 解码改像素格式吗 | ❌ 不改——BMP 本就不压缩,解码头后像素还是 BGR0 |
| 和 rawdec 的关系 | 无关。BMP 解码器服务 `AV_CODEC_ID_BMP`；rawdec 服务 `AV_CODEC_ID_RAWVIDEO`（裸像素文件、`-f rawvideo`、或设备协商成 rawvideo 时）。两者是同一角色(packet→frame)的不同解码器 |
| 能跳过吗 | 不能直接跳过——包里有 40 字节头,必须解析才知道宽高/stride;不像 rawvideo 可以手动塞壳 |

**真正省不掉的是 BGR0 → YUV420P 格式转换**(sws_scale)。mpeg4 编码器的 `pix_fmts` 白名单里没有 BGR0,只接受 YUV 家族。视频链路:

```
gdigrab BitBlt → AVPacket(BMP: 头 + BGR0 裸像素)
  → BMP 解码(解头 + 拷像素,无压缩算法)
  → 水印(QPainter 改像素值)
  → sws_scale BGR0→YUV420P     ← 真正省不掉的格式转换
  → mpeg4 编码
  → 封装 MP4
```

### 音频录音(dshow 解码)

音频解码和视频 BMP 解码完全不同——**它可能是真解码**。dshow 声卡输出格式不确定:

| 维度 | dshow 可能给的 | AAC 编码器硬要求 |
|------|----------------|------------------|
| 样本格式 | S16LE / S24LE / F32LE / U8 / AAC 压缩 | FLTP(planar float) |
| 采样率 | 44100 / 48000 / 96000 | 48000 |
| 声道布局 | 单声道 / 立体声 / 5.1 | 立体声(2 声道 FLTP) |
| 每包样本数 | 不定(驱动决定) | 1024(AAC 固定帧大小) |

两种情况:

1. **声卡输出 PCM 裸数据**(大多数情况):解码后拿到 PCM AVFrame,解码性质和视频 BMP 解码类似(无压缩算法,主要是拷贝)。但**swr_convert 必须在解码后的 AVFrame 上做**——重采样器只接受 AVFrame 输入,不认 AVPacket。

2. **声卡输出压缩格式**(如 AAC):这时候解码是真解码——熵解码 → 反量化 → IMDCT,彻底改变数据形态。**不解码根本拿不到 PCM 样本**。

音频解码后还要做视频没有的事:
- **swr_convert**:样本格式(S16→FLTP) + 采样率(重采样) + 声道布局(交错→planar)三重转换
- **FIFO 攒帧**:dshow 每次给的包大小不定,但 AAC 编码器要求每帧恰好 1024 样本,必须解码后才能按样本粒度攒够帧

音频链路:

```
dshow 声卡 → AVPacket(PCM 裸样本 或 AAC 压缩包)
  → 解码(真解码或壳子填充)      ← 硬需求,绝不能跳过
  → swr_convert → FLTP 48kHz   ← 格式转换,硬省不掉
  → 倍率下采样(每 N 样本取 1)
  → av_audio_fifo_write          ← 音频独有:攒够 AAC 的 1024 样本帧
  → DrainFifo: 1024 样本帧送 AAC 编码
  → 封装 MP4
```

### 两者对比

| 维度 | 视频 gdigrab(BMP 解码) | 音频 dshow 解码 |
|------|------------------------|-----------------|
| 解码前内容 | BMP:40B 头 + 未压缩 BGR0 像素 | 可能是 PCM 裸样本,也可能是压缩包 |
| 解码后格式变化 | **不变**(还是 BGR0) | **可能变**(压缩格式解出来才是 PCM) |
| 解码性质 | 无压缩算法:解头 + 拷像素 | 真解码(压缩)或无压缩算法(拷样本) |
| 能跳过吗 | 不能:必须解析头拿宽高/stride | 压缩格式绝不能;PCM 时理论能但没必要 |
| 下游硬需求 | sws_scale BGR→YUV | swr_convert + FIFO 攒帧 |
| 为什么不能不解码 | FFmpeg 下游只接 AVFrame | FFmpeg 下游只接 AVFrame + 声卡格式不确定 + FIFO 必须解码后才能攒 |

### 最终结论

解码本身不是为了"把压缩数据解开"——gdigrab 给的是未压缩 BMP,根本没有压缩可解;解码是为了满足 FFmpeg 的 API 契约:**所有像素/样本级操作(格式转换、滤镜、水印、下采样、FIFO)都必须在 AVFrame 上进行,而 AVFrame 只能通过解码器从 AVPacket 获得**。

视频的 BMP 解码可以看作"最轻量的解包器"——解析 40 字节位图头,把后面的裸像素拷进 AVFrame,不做任何熵解码/反量化。音频的解码则可能**是不可替代的真解码**——声卡若输出压缩格式,不解码根本拿不到 PCM;而且 AAC 编码器的输入要求(FLTP、48kHz、1024 样本帧)和声卡输出之间必须有解码 + 重采样 + FIFO 攒帧这一整套处理。
